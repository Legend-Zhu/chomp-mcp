> # 项目描述：scse-chomp-mcp（带 digest 能力的联网调研 MCP server）
> 
> ## 项目定位
> 为 scse-agent（以及任何遵循 MCP 协议的 LLM 客户端）提供"开箱即用、自带摘要（digest）"的联网调研能力。解决 LLM agent 的"信息茧房"问题：当用户需求涉及 agent 不熟悉的外部框架、开源项目、依赖库、API、最新技术时，agent 可以通过本 MCP server 联网调研，并直接拿到结构化的精炼结论，而不是一堆原始网页链接。
> 
> 核心理念：**调用方永远收到精炼摘要，绝不收到原始网页正文**，从而避免长内容污染 agent 上下文。
> 
> ## 技术栈
> - 语言：TypeScript（Node.js 18+），ESM 模块
> - MCP 协议：@modelcontextprotocol/sdk，stdio 传输（JSON-RPC over stdin/stdout）
> - 无任何付费第三方 API 依赖；零 API key 要求（除最后的 LLM 摘要复用调用方配置的 LLM）
> 
> ## 架构：Search → Scrape → Deduplicate → LLM-Synthesize 四段 pipeline
> 
> 本 MCP server 的核心是一条可复用的调研 pipeline，所有对外工具都基于这条 pipeline 构建：
> 
> 1. **Search（搜索）**：调用 SearXNG 元搜索引擎（聚合 Google/Bing/DuckDuckGo 等多个引擎结果），获取候选结果列表（标题、URL、摘要片段）。SearXNG 零 API key、零费用、隐私友好。
> 
> 2. **Scrape（抓取）**：对候选 URL 并发抓取网页正文。主路径使用轻量纯 Node 方案：HTTP 请求 + cheerio 解析 HTML + @mozilla/readability 提取正文（Firefox 阅读模式同款算法）。遇到需要 JavaScript 渲染的页面（如部分 SPA 文档站点），降级使用 Puppeteer 无头浏览器渲染后再提取。每页正文做长度截断（可配置上限，默认每页 8000 字符），防止单页过长。
> 
> 3. **Deduplicate（去重降噪）**：搜索结果常有同一内容多源转载（同一篇文章出现在多个博客/CSDN/掘金）。先做 URL 规范化（去 tracking 参数、统一协议、去 fragment），再做内容级去重（基于段落指纹，如对正文分段后取 hash 集合比对相似度，相似度超阈值的视为重复只保留得分最高的一条）。去重是保证后续摘要质量的关键——不降噪会被噪音淹没。
> 
> 4. **LLM-Synthesize（LLM 摘要）**：把去重后的多段正文喂给 LLM，产出针对原始查询的结构化摘要。这是整个 pipeline 的灵魂：LLM 不是简单拼接，而是综合多个来源、去伪存真、提炼出"这个问题/这个库/这个技术的关键事实、核心用法、集成方式、注意事项"。摘要格式为结构化文本，包含：直接回答（Answer）、关键要点（Key Points）、来源引用（Sources，含 URL）。**LLM 配置通过环境变量注入**（见下方配置），MCP server 内部调用 LLM，调用方无需关心。
> 
> ## 对外工具（MCP tools）
> 
> 本 MCP server 对外暴露两个工具，二者都内置完整或部分 pipeline，且都内置 LLM Synthesize，调用方永远拿到精炼结果：
> 
> ### 工具 1：web_search
> - 用途：对一个查询（query）做完整联网调研，返回结构化摘要。这是主工具，覆盖"我不了解 X，帮我查清楚"的场景。
> - 参数：
>   - `query`（string，必填）：调研查询，例如 "如何用 TypeScript 实现 MCP server"、"RuoYi-Vue3 最新版本如何集成 MyBatis-Plus"
>   - `max_results`（integer，可选，默认 5）：从 SearXNG 拉取并进入 pipeline 的最大候选结果数（影响耗时和摘要质量，建议 3-8）
>   - `focus`（string，可选）：调研焦点提示，引导摘要侧重某个方面，例如 "集成步骤" / "API 用法" / "版本兼容性"
> - 返回：结构化摘要文本（Answer + Key Points + Sources），非原始网页。
> 
> ### 工具 2：web_fetch
> - 用途：对一个已知的具体 URL 做抓取 + 摘要，返回该页关键信息。覆盖"我已经知道要看这个文档/repo/页面，帮我提取要点"的场景。
> - 参数：
>   - `url`（string，必填）：目标 URL
>   - `focus`（string，可选）：提取焦点，例如 "安装方法" / "配置参数" / "CHANGELOG"
> - 返回：该页的结构化摘要文本，非原始正文。
> 
> ## 模块划分
> 
> 本项目按职责拆分为以下模块（供需求阶段进一步细化 User Stories）：
> 
> ### 模块 SR（search-retrieval）：搜索获取
> 负责调用 SearXNG、解析返回的 JSON、规整成统一的候选结果结构（title/url/snippet/score）。处理 SearXNG 公共实例不可达时的错误、超时、重试。支持通过环境变量切换到自托管的 SearXNG 实例。
> 
> ### 模块 SC（scrape-extract）：抓取提取
> 负责把 URL 转成纯文本正文。主路径 cheerio+readability，降级路径 Puppeteer。处理 HTTP 错误（404/403/超时）、编码识别、正文长度截断、非 HTML 资源（如直接是 JSON/XML 的 API 文档）的特殊处理。
> 
> ### 模块 DD（deduplicate）：去重降噪
> 负责 URL 规范化和内容级去重。URL 规范化：去 utm_* 等 tracking 参数、统一大小写、去 fragment、统一尾斜杠。内容去重：对正文分段、计算段落指纹、比对相似度、合并近重复项。
> 
> ### 模块 SY（synthesize）：LLM 摘要
> 负责与 LLM 交互产出结构化摘要。封装 LLM 客户端（OpenAI 兼容接口），管理摘要 prompt（要求产出 Answer/Key Points/Sources 结构、要求引用来源 URL、要求简洁），处理 LLM 调用失败、超时、token 超限（分批摘要后再合并）。
> 
> ### 模块 PL（pipeline-orchestration）：编排层
> 负责把上述四段编排成完整的 web_search 工具流程，以及 web_fetch 的子流程（Scrape→Synthesize）。管理并发抓取的并发度限制、整体超时、错误隔离（单个 URL 失败不影响整体）。
> 
> ### 模块 MC（mcp-server）：MCP 服务入口
> 负责 MCP server 的生命周期：stdio transport 监听、JSON-RPC 消息处理、工具定义注册（web_search/web_fetch 的 inputSchema）、工具调用分发到 PL 编排层、工具响应格式化。这是 scse-agent（或任何 MCP 客户端）连接的入口。
>

## 项目概述

**chomp-mcp** 是一个 MCP（Model Context Protocol）服务器，为 LLM agent 和任何兼容 MCP 的客户端提供"开箱即用、自带摘要（digest）"的联网调研能力。它解决了"信息茧房"问题：当用户需求涉及 agent 不熟悉的外部框架、开源项目、依赖库、API 或最新技术时，agent 可以通过本 MCP server 联网调研，并直接拿到结构化的精炼结论，而不是一堆原始网页链接。

**核心理念：** 调用方永远收到精炼摘要，绝不收到原始网页正文，从而避免长内容污染 agent 的上下文窗口。

### 架构：Search → Scrape → Deduplicate → LLM-Synthesize

服务器的核心是一条可复用的调研 pipeline，两个对外工具都基于这条 pipeline 构建：

1. **搜索（Search）** — 调用 SearXNG 元搜索引擎（聚合 Google/Bing/DuckDuckGo 等多个引擎结果），获取候选结果（标题、URL、摘要片段）。SearXNG 零 API key、零费用、隐私友好。
2. **抓取（Scrape）** — 对候选 URL 并发抓取网页正文。主路径：HTTP 请求 + jsdom + @mozilla/readability 提取正文。降级路径：Puppeteer 无头浏览器渲染 JavaScript 页面。每页正文做长度截断（可配置上限，默认 8000 字符）。
3. **去重（Deduplicate）** — URL 规范化（去 tracking 参数、统一协议/fragment）+ 内容级去重（段落指纹 + Jaccard 相似度比对）。近重复项合并，保留得分最高的一条。
4. **LLM 摘要（Synthesize）** — 将去重后的内容喂给 LLM，产出结构化摘要（Answer + Key Points + Sources 含 URL）。Token 超限时分批摘要后合并。LLM 失败时降级返回截断的原始内容。

### 模块交互方式

```
MCP 客户端 (stdio JSON-RPC)
    │
    ▼
┌─────────────────────────────────┐
│  MC (mcp-server)                │  工具分发、参数校验、响应格式化
│  web_search / web_fetch         │
└──────────────┬──────────────────┘
               │
               ▼
┌─────────────────────────────────┐
│  PL (pipeline-orchestration)    │  并发控制、超时管理、错误隔离
│  runWebSearch / runWebFetch     │
└──┬──────┬──────┬──────┬─────────┘
   │      │      │      │
   ▼      ▼      ▼      ▼
  SR      SC      DD      SY
 搜索    抓取    去重    摘要
```

- **web_search** 流经全部四个阶段：SR → SC → DD → SY
- **web_fetch** 流经两个阶段：SC → SY

## 快速开始

### 前置条件

- **Node.js** 18 LTS 或更高版本
- **npm**（随 Node.js 安装）
- 一个 **LLM API key**（OpenAI 兼容）— 摘要阶段必需

### 1. 安装依赖

```bash
npm install
```

### 2. 构建项目

```bash
npm run build
```

此命令运行 `tsc`，将编译后的 JavaScript 输出到 `dist/` 目录。

### 3. 运行 MCP 服务器

#### 生产模式（编译后）

```bash
LLM_API_KEY="sk-your-api-key" node dist/index.js
```

#### 开发模式（使用 tsx，无需构建）

```bash
LLM_API_KEY="sk-your-api-key" npm run dev
```

### 4. 类型检查（不输出文件）

```bash
npm run typecheck
```

### 5. 运行测试

```bash
npm test
```

### 环境变量

所有配置均通过环境变量完成 — 零配置文件。

| 变量 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `LLM_API_KEY` | **是** | — | LLM 服务的 API key（OpenAI 兼容） |
| `LLM_BASE_URL` | 否 | `https://api.openai.com/v1` | LLM API 基础 URL |
| `LLM_MODEL` | 否 | `gpt-4o-mini` | 摘要使用的模型名 |
| `SEARXNG_URL` | 否 | 公共实例 | SearXNG 搜索端点（自托管 URL） |
| `SCRAPE_TIMEOUT_MS` | 否 | `15000` | 单页抓取超时（毫秒） |
| `MAX_CONTENT_CHARS` | 否 | `8000` | 单页正文最大字符数 |
| `MAX_CONCURRENCY` | 否 | `3` | 并发抓取数限制 |
| `DEDUP_SIMILARITY_THRESHOLD` | 否 | `0.85` | 近重复检测的 Jaccard 阈值 |
| `MIN_PARAGRAPH_CHARS` | 否 | `20` | 指纹计算的最小段落长度 |
| `DEDUP_EXTRA_TRACKING_PARAMS` | 否 | （空） | 额外需要去除的 tracking 参数（逗号分隔） |

### 自托管 SearXNG

`web_search` 最好配合自托管 SearXNG 使用。下面示例会把 SearXNG 跑在 `127.0.0.1:8080`，开启 JSON 响应，并优先使用 Bing，因为在部分网络环境下 Google、DuckDuckGo、Brave、Startpage 等公共搜索引擎可能较慢或不可用。

创建本地 SearXNG 目录：

```bash
mkdir -p ./searxng-local
cd ./searxng-local
```

创建 `settings.yml`：

```yaml
use_default_settings: true

server:
  secret_key: "<替换为随机密钥>"
  limiter: false
  image_proxy: false

search:
  safe_search: 0
  autocomplete: ""
  formats:
    - html
    - json

ui:
  static_use_hash: true

outgoing:
  request_timeout: 10.0
  max_request_timeout: 15.0

engines:
  - name: bing
    engine: bing
    shortcut: bi
    disabled: false
    base_url: https://cn.bing.com
  - name: google
    disabled: true
  - name: duckduckgo
    disabled: true
  - name: brave
    disabled: true
  - name: startpage
    disabled: true
  - name: wikipedia
    disabled: true
  - name: wikidata
    disabled: true
```

创建 `docker-compose.yml`：

```yaml
services:
  searxng:
    image: ghcr.io/searxng/searxng:latest
    container_name: searxng-local
    restart: unless-stopped
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - ./settings.yml:/etc/searxng/settings.yml:ro
    environment:
      - SEARXNG_BASE_URL=http://127.0.0.1:8080/
```

如果当前网络拉取 `ghcr.io` 镜像较慢，可以替换成可信镜像代理，但容器配置保持不变。

启动 SearXNG：

```bash
docker compose up -d
```

验证 JSON 搜索：

```bash
curl 'http://127.0.0.1:8080/search?q=Model%20Context%20Protocol&format=json'
```

chomp-mcp 中使用这个值：

```bash
SEARXNG_URL="http://127.0.0.1:8080"
```

不要在 `SEARXNG_URL` 里包含 `/search`，chomp-mcp 内部会自动拼接 `/search`。

### 从 MCP 客户端接入

将服务器添加到 MCP 客户端配置中，例如 Trae 或 Claude Desktop。下面是脱敏示例：路径、API key、base URL 和模型名需要替换成你自己的值。

```json
{
  "mcpServers": {
    "chomp-mcp": {
      "command": "node",
      "args": [
        "<CHOMP_MCP_绝对路径>/dist/index.js"
      ],
      "env": {
        "LLM_API_KEY": "<已脱敏的_LLM_API_KEY>",
        "LLM_BASE_URL": "<OpenAI兼容接口地址>",
        "LLM_MODEL": "<模型名称>",
        "LLM_TIMEOUT_MS": "120000",
        "LLM_MAX_CONTEXT_TOKENS": "1000000",
        "SEARXNG_URL": "http://127.0.0.1:8080",
        "SEARXNG_TIMEOUT_MS": "15000",
        "SCRAPE_TIMEOUT_MS": "30000",
        "MAX_CONTENT_CHARS": "30000",
        "MAX_CONCURRENCY": "2",
        "PIPELINE_TIMEOUT_MS": "240000"
      }
    }
  }
}
```

接入后，客户端将自动发现 `web_search` 和 `web_fetch` 工具。

示例提示词：

```text
用 chomp-mcp 搜索 “Model Context Protocol”，并总结技术细节。
```

```text
用 chomp-mcp 抓取 https://modelcontextprotocol.io/docs/getting-started/intro，并总结核心概念。
```

## API 概览

本服务器通过 stdio JSON-RPC 传输暴露两个 MCP 工具。没有 HTTP REST 端点 — 所有通信通过 stdin/stdout 使用 MCP 协议进行。

### 工具：`web_search`

执行完整的联网调研 pipeline（搜索 → 抓取 → 去重 → 摘要），返回结构化摘要。

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `query` | string | 是 | — | 调研查询（最长 500 字符） |
| `max_results` | integer | 否 | `5` | 从 SearXNG 拉取的最大候选结果数（建议 3–8） |
| `focus` | string | 否 | — | 调研焦点提示，引导摘要侧重（最长 500 字符） |

**返回：** 结构化摘要文本，包含：
- **Answer** — 针对查询的直接综合回答
- **Key Points** — 关键要点列表
- **Sources** — 引用的来源 URL 及标题

### 工具：`web_fetch`

抓取指定 URL 并合成其内容的结构化摘要（抓取 → 摘要）。

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `url` | string | 是 | — | 目标 URL |
| `focus` | string | 否 | — | 提取焦点提示（最长 500 字符） |

**返回：** 结构化摘要文本（格式同 `web_search`）。

### 响应格式

所有工具响应均为 MCP 标准的 `content` 数组（`type: "text"`）。文本内容即结构化摘要。错误响使用 `isError: true` 并附带可读的错误信息。超过 25,000 字符的响应会被截断并附加标记。

## 模块说明

### MC — MCP 服务器（`src/modules/mcp-server/`）

MCP 协议入口。管理服务器生命周期、stdio 传输、工具注册、参数校验（Zod）以及工具调用分发到 pipeline 编排层。所有处理器均包裹在 try/catch 中以确保服务器稳定性。

**关键文件：** `server.ts`（生命周期）、`tool-definitions.ts`（工具模式）、`tool-handlers.ts`（分发）、`validation.ts`（Zod 校验）

### PL — Pipeline 编排（`src/modules/pipeline-orchestration/`）

端到端 pipeline 协调器。编排 `web_search` 的搜索 → 抓取 → 去重 → 摘要流程和 `web_fetch` 的抓取 → 摘要流程。管理并发限制（基于 Semaphore）、整体 pipeline 超时（AbortController）和单 URL 错误隔离。

**关键文件：** `orchestrator.ts`（入口 + 配置）、`web-search-pipeline.ts`、`web-fetch-pipeline.ts`、`concurrency-limiter.ts`、`timeout-guard.ts`

### SR — 搜索获取（`src/modules/search-retrieval/`）

SearXNG 元搜索客户端。向 SearXNG 发送 HTTP GET 请求，解析 JSON 响应，规范化结果（分数归一化、URL 去重、字段截断）。支持自托管和公共实例模式，具备自动故障转移和指数退避重试。

**关键文件：** `searxng-client.ts`（HTTP 客户端）、`response-parser.ts`（JSON 解析）、`result-normalizer.ts`（规范化）、`retry-failover.ts`（重试逻辑）、`instance-pool.ts`（实例轮换）、`errors.ts`（错误层级）

### SC — 抓取提取（`src/modules/scrape-extract/`）

URL 到纯文本的提取。主路径：原生 `fetch` + jsdom + @mozilla/readability。降级路径：Puppeteer 无头浏览器渲染 JavaScript 页面。处理 HTTP 重定向、超时、字符集检测（iconv-lite）、Content-Type 路由（HTML/JSON/XML/text/binary）、词边界截断和 SSRF 防护（私有 IP 阻断）。

**关键文件：** `scraper.ts`（编排器）、`http-fetcher.ts`（带重试的 HTTP）、`content-extractor.ts`（Readability）、`puppeteer-renderer.ts`（JS 渲染）、`content-type-router.ts`、`encoding-detector.ts`、`truncator.ts`、`url-validator.ts`

### DD — 去重降噪（`src/modules/deduplicate/`）

纯去重和降噪转换。URL 规范化去除 tracking 参数（utm_* 等）、统一协议/端口/fragment。内容级去重使用段落分割、FNV-1a 32 位指纹和 Jaccard 相似度比对。近重复项通过 Union-Find 合并，保留得分最高的条目。永不抛出异常 — 所有错误均被捕获并记录。

**关键文件：** `deduplicator.ts`（pipeline 入口）、`url-normalizer.ts`、`paragraph-segmenter.ts`、`fingerprinter.ts`、`similarity-computer.ts`、`content-merger.ts`、`stats.ts`

### SY — LLM 摘要（`src/modules/synthesize/`）

LLM 驱动的摘要合成，产出结构化 digest。初始化 OpenAI 兼容客户端，构建系统/用户 prompt，调用 LLM 并带重试（瞬态错误指数退避，超时单独重试）。Token 超限时通过分批摘要后合并处理。不可恢复的失败时降级为从原始内容生成 fallback digest。永不向调用方 reject Promise。

**关键文件：** `synthesizer.ts`（编排器）、`llm-client.ts`（客户端 + 重试）、`prompt-builder.ts`（prompt）、`response-parser.ts`（多策略解析）、`batch-merger.ts`（Token 超限）、`degradation-handler.ts`（降级）、`token-estimator.ts`（中英文感知）

### 共享层（`src/shared/`）

跨模块类型定义（`SearchResult`、`ScrapeResult`、`ContentItem`、`DeduplicatedItem`、`DigestResult`、`SourceRef`），`AppError` 基类（带 `ErrorCategory` 区分字段），以及工具函数（日志、环境变量解析、Semaphore、URL 辅助）。
